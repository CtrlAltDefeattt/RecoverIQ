# Maintainers

RecoverIQ currently uses a maintainer-led governance model appropriate for an
early-stage project.

## Primary maintainer

- [@CtrlAltDefeattt](https://github.com/CtrlAltDefeattt) — architecture,
  roadmap, issue triage, pull-request review, security coordination, CI,
  documentation, and releases.

## Decision process

Routine fixes are accepted when they are scoped, tested, documented where
needed, and consistent with the project architecture. The primary maintainer
makes final decisions after considering contributor feedback.

Changes to payment execution, safety rules, learning boundaries, stored event
contracts, or published evaluation methodology receive additional scrutiny.
They must include tests and an explicit discussion of failure modes.

## Becoming a maintainer

Consistent contributors may be invited to take responsibility for an area after
demonstrating sound review judgment, reliable follow-through, and respect for
the project's safety and evidence standards. Maintainer changes will be
recorded in this file.

## Security

Security reports follow [SECURITY.md](SECURITY.md) and must not be discussed in
public issues until a fix and disclosure plan are agreed.
